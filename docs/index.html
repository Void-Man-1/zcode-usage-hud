Capabilities

Everything the metered plans
don't tell you.

Built from the same dark-panel language as the HUD itself: near-black canvas, hairline borders, one accent where it means something.

Per-bucket truth, not averages

Every quota the billing API returns gets its own card — DAILY, WEEKLY, MONTHLY, or one-time PROMO — with used/left math, exact local refill timestamps, and an amber warning when a promo pool expires instead of refilling.

GLM-5.3 · DAILY
refills 00:00 local · 1.86M of 3.0M left
62%

A strip, not a window

Collapse to a slim always-on-top strip that stacks full-width rows per bucket — glanceable without stealing desktop.

Standalone sign-in

Browser-based Google OAuth through Z.AI — no ZCode app required. The HUD mints and stores its own device identity when the app is absent, then defers to the app's when present.

Works app-freeself-managed device ID, persisted locally
AES-GCM credential store0600 file modes, tokens masked in logs

Promo grants, counted down to activation

Accepted-but-not-yet-spendable grants get their own section — activation countdown, grant size, covered models, and the exact moment the offer window closes.

$ zcode-usage-hud --dump { "SignedIn": true, "Balances": [ "GLM-5.3", "GLM-5.3-Flash" ], "PendingGrants": 2 // activating in 02:34:51 }

Install

Two minutes, one installer.

Installer

Grab ZCode-Usage-HUD-v1.2.2-Setup.exe from the project's releases, run it — it installs per-user under %LOCALAPPDATA%\Programs and registers Start-with-Windows if you ask it to.

From source

$ git clone <repo> zcode-console $ cd zcode-console $ go build -trimpath -ldflags "-H=windowsgui -s -w" .
